Website Integration & Portal Architecture Guide

Architectural options and implementation blueprints for integrating the DATAEKO × meshIQ Economic Assessment tool into public-facing marketing portals.

1. Recommended Approach: Marketing Portal CTA → Separately Hosted App Recommended

The enterprise best-practice architecture is to keep marketing portals (e.g. dataeko.ai) and specialized transactional software applications (e.g. the Partner Dashboard) independently hosted.

In this model, the DATAEKO.AI partner page introduces the assessment value proposition and provides a clear call-to-action that routes users to the dedicated assessment application, where authentication is handled by the application.

DATAEKO.AI Marketing Site (https://dataeko.ai)
↓
Partner Showcase Page (/partners/meshiq)
↓
Existing "Visit meshIQ.com" & Hero Section
↓
DATAEKO × meshIQ Assessment Section / CTA Card
↓
"Start Assessment" (or "Launch Partner Calculator")
↓
Separately Hosted Assessment App (https://YOUR-ASSESSMENT-DOMAIN/meshiq)

Why This Approach is Superior:

  • Security & Session Cookies: The application relies on secure HTTP-only cookies (SameSite=Lax). Independent hosting prevents cross-site third-party cookie restrictions in Safari, Chrome, and iOS.
  • Independent Release Cycles: Engineering can deploy dashboard updates, new calculation scenarios, or PDF template enhancements without risking marketing CMS downtime.
  • Responsive Viewports: The assessment wizard features rich interactive tables, sliders, charts, and modal dialogs that perform best when rendered in full viewport dimensions rather than bounded frames.
  • Performance: No overhead from marketing page tracking scripts, heavy web fonts, or CMS stylesheets interfering with application execution.

2. Optional Future Architecture: iframe Embedding Optional Future Architecture

Optional future architecture — not implemented or tested as a production integration.

An alternative conceptual approach is embedding the assessment tool inside an <iframe> on the partner page. While technically feasible, it introduces operational and security considerations that must be evaluated:

Architecture Consideration Dedicated Application (Recommended) iframe Embed (Alternative)
Authentication & Cookies Standard First-Party HTTP-only cookies. Zero browser blocking. Requires SameSite=None; Secure third-party cookies, which modern browsers restrict by default.
Content Security Policy (CSP) Standard origin policy. Complete clickjacking protection. Requires permissive frame-ancestors allowing dataeko.ai and meshiq.com.
Mobile & Tablet Viewport Full responsive control, sticky section steps, touch-friendly. Often triggers nested scrollbars and clipped modal dialogs on mobile viewports.
PDF & Deliverable Download Direct browser downloads with native PDF previewers. Requires specific iframe permissions (allow-downloads, allow-popups).

If iframe Embedding is Chosen by Management:

If management decides to implement iframe embedding in the future, the backend will require adjusting CSP headers and cookie flags as follows:

# Required backend configuration if embedded within an iframe:
# 1. Content Security Policy:
Content-Security-Policy: frame-ancestors 'self' https://dataeko.ai https://*.dataeko.ai https://meshiq.com;

# 2. Session Cookie Flag:
Set-Cookie: access_token=...; SameSite=None; Secure; HttpOnly;

3. Production Deployment & Domain Checklist

When preparing the production deployment, the following steps should be completed by the DevOps or project lead:

  1. Domain Provisioning: Allocate a subdomain such as meshiq-assessment.dataeko.ai or partners.dataeko.ai/meshiq.
  2. SSL / TLS Termination: Ensure HTTPS is enforced with valid enterprise certificates.
  3. Environment Variables: Configure production API URLs, secure database connection strings, and strong JWT secrets (never use dev defaults in production).
  4. CORS Configuration: Set BACKEND_CORS_ORIGINS to include the authoritative portal domain.
  5. Portal Link Update: Replace all https://YOUR-ASSESSMENT-DOMAIN/meshiq placeholders on marketing pages with the authoritative live URL.
